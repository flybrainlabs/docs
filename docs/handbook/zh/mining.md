# 挖矿流程

挖矿在冻结的刺激空间中搜索满足已登记数值目标的响应。它使用完整准备后的图，并记录所有必需背景。只有属于已准入、已提供预算的发现单位，任务才可能得到付款。

## 先连接钱包

挖矿主入口先要求连接 Wallet Standard 钱包，再完成登录。选择“连接钱包”不会开始仿真，也不会下载完整模型。之后查看准备状态、可用任务和有限额度。连接钱包不能重新打开已经完成的预算。

## 阅读当前准备阶段

:::diagram preparation

**下载大脑数据。** 浏览器获取登记资源、跟踪字节并核验声明摘要。成功的数据块保留供后续会话使用。

**构建大脑模型。** 准备控制器使用已校验资源构建可执行表示。下载完成和模型就绪是不同检查点。

**开始挖矿。** 满足前提后，用户主动启动，浏览器 Worker 与 WebAssembly 数值核心搜索符合条件的候选。界面聚焦当前阶段。

只有当前阶段标题和控件可见。模型就绪后，下载与构建标题会隐藏，但不会删除缓存。模型准备状态和任务可用性分别显示。

最初 Devnet 验收计划已完成。另一个冻结的 2 FBW 任务供给阶段支持两个新增校准目标，每个唯一且验证通过的赢家可获 1 FBW。任务服务有开放目标时，页面显示**当前目标开放**及轮次证据。连接并登录钱包，准备或恢复模型，并具备有效的有限租金额度后才能开始奖励工作。供给耗尽时，**检查新任务**仅同步可用性，不启动 Worker。就绪模型和可用任务始终是独立前提。

## 工作控制与指标

| 控件或数值 | 含义 |
| --- | --- |
| 线程设置 | 选择并行计算容量；增加线程可能增加内存压力 |
| 实际吞吐量 | 计算过程中测得的每秒神经更新量 |
| 进度 | 当前试验或背景范围内已完成的工作 |
| 暂停 / 恢复 | 暂停并继续受控工作 |
| 停止 | 结束当前工作路径；需检查真正完成和保留了什么 |
| 保存 / 导出 | 主动保存可恢复成果或数据包 |
| 图形开关 | 独立控制可视化，不改变科学计算 |
| 日志 | 当前会话的准备、计算、提交和失败信息 |

吞吐量是性能指标，不是资格评分或奖励公式。验证关注是否完成全部必需背景；耗时和线程数量不会独立产生报酬。

## 从候选到结果

:::diagram competition

首先按冻结规则在本地评估候选。达标候选提交承诺，经私有路径上传完整背景材料，再进行揭示。有预算的 V3 工作必须在科学承诺前完成资金意图的 finalized 确认。

获准验证者复算**所有必需背景**。任务服务按回执顺序选择最早且合格、验证通过的承诺。更快的本地时钟或更早完成验证不会改变规则。[任务与竞争](/docs/tasks/)解释资格和截止时间。

## 理解不同状态

本地达标不代表已上传；上传接受不代表复算通过；验证通过不代表获胜；科学获胜不代表收到代币。奖励实际收到，需要绑定原受益人的 finalized 资金证据。

阶段没有剩余任务时，界面等待新的校准供给。重复已解决任务、更改名称或钱包都不会创建新的可付款发现。

## 中断与恢复

保留保存的候选、模型数据块和快照。刷新页面不会自动开始另一次运行。恢复前先检查冻结身份和可用存储；即使科学状态已终结，已接受资金意图仍会继续对账。

不要为修复图形或 RPC 错误删除完整缓存。持久化说明见[模型缓存与恢复](/docs/storage/)，针对性操作见[故障排查](/docs/troubleshooting/)。
