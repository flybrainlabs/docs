# 经济模型

经济设计通过**有限阶段**为可验证科研工作提供预算。参与前，阶段公布资金来源、预留金额、任务单位、验收规则、期限、受益人和剩余资金处理方式。

供应上限描述资产发行设计，不产生价格、流通价值、保证收入或无限挖矿预算。

## 供应量与固定发行分配

EconomicPolicyV2 规定八位小数和 **311,833,243 枚代币**，即 **31,183,324,300,000,000 atoms**。准确分配如下：

| 池 | 代币数量 | Atoms | 用途 |
| --- | --- | --- | --- |
| 矿工 | 224,519,936 | 22,451,993,600,000,000 | 有限合格贡献预算 |
| 验证服务 | 56,129,984 | 5,612,998,400,000,000 | 预留验证服务工作 |
| 社区 / 生态 | 31,183,323 | 3,118,332,300,000,000 | 明确社区与生态分配 |
| 总计 | 311,833,243 | 31,183,324,300,000,000 | 精确初始上限 |

项目代币为 **flybrainwork / FBW**。既有 Devnet 资产采用这些供应和分配值，其存在不代表生产资产已配置或 Marketplace 付款路径已激活。

既有测试资产已撤销 mint 权限，且没有冻结权限。合法持有人销毁可使当前供应低于已验证初始上限，不表示资产伪造，也不授权再次发行。

## 有限任务与分配

可付款发现使用唯一任务或单位，并在参与前预留金额。覆盖、验证、额外读出和整理各需独立冻结合同及预算。预算之外的成功试验不会自动成为欠款。

分配使用经过检查的整数 atoms。累计分配政策可采用 `floor((k + 1) × P / M) − floor(k × P / M)`，P 为池，M 为单位数。不能替换为 JavaScript 浮点账务或历史整币规则。

新阶段可准入额外任务，同时保留已有权益。已解决的语义任务不能通过钱包或展示名称变更循环领取发现付款。

## 三本关联账簿

:::diagram ledgers

**科学账**记录计算、复算和结果；**权利账**记录已接受且获准的权益；**资金账**记录预留、已接受负债、在途转账和最终付款。这些资金状态是同一义务的互斥表示。

科学获胜不等同于代币到账。界面只在 finalized 付款证据后报告已收到资产。

## 本金、费用与退款

报价和计划分别列明执行、复算、归档、传输、网络费、账户租金本金、存款和预付款。Result 数据长度不代表总成本。

可退款余额不包含已接受义务、在途付款和服务负债，按计划退给冻结接收方。未领取的已接受权益不能任意行政清扫。新存款和未使用预付款默认可退，除非另有明确协议。

RPC 超时、历史缺失或 blockhash 到期本身不能证明转账未执行。持久化对账确定真实结果前，原始负债保持锁定。

## 收入与历史权益

发行不是销售收入，存款不是利润，预付款不是已完成收入。不同资产分别记账；缺少汇率时，价值未知而不是零。

拟议 Marketplace 需要累计历史权益、领取、退款限额和精确继承。主机测试的基础模块不代表已部署收费服务。剩余闭环见 [Marketplace 路线图](/docs/marketplace/)。

## 社区预算与积分

既有 31,183,323 FBW 社区与生态池中，25,000,000 FBW 作为未来社区空投预算，6,183,323 FBW 留给其他生态用途。约 80.17% 的比例针对该池，不是总供应。积分与排名是贡献记录，不是代币，没有固定兑换比例、保证个人金额或日期。真实分发前必须批准冻结快照并公布规则。预算不改变冻结的 EconomicPolicyV2 字节，也不增发代币。见 [Social](/social/)与[社区指南](/docs/social/)。
